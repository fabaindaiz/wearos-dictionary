# Words an English dictionary HAS to be able to find.
#
# Same pattern as `normalization-vectors.tsv`: the file of expectations IS the mechanism.
# `verify_pack.py` runs it on its own when the pack declares `en`, and fails naming what is
# missing.
#
# ⚠️ **What this does NOT solve, and it has to be said.** A hand-written list carries the same
# bias as looking by hand: it does not know what nobody thought to put in it. It defends against
# **regressions** -- a prune that takes half the calendar, a filter that empties 39.6 % of the
# entries -- and not against unknown holes. There is no shortcut for those.
#
# ⚠️ **Adding a word here is recording a product decision**, not padding a test: it asserts that
# this dictionary is broken without it. Hence the groups, and hence each group saying what it
# defends.
#
# A word counts as found if it is a lemma of the pack **or** one of its inflected forms: `went`
# reaches `go`, which is exactly what the user experiences when searching for it.

# Words that carry today's meaning. Defends the finding that made OEWN a spike and not a source:
# it covered 64 % of a 39-word probe because it is frozen academic vocabulary (D-120).
#
# ⚠️ **This group binds the FULL pack only, and the reason is measured.** What it defends is that
# the *source* carries current vocabulary -- not that a cut is sane. And a cut by frequency
# cannot deliver these: `blockchain`, `deepfake` and `workaround` have **zero** occurrences in
# `freq-en-opensubs.txt`, so no frequency-ordered tier will ever reach them. Demanding them of a
# `core` turns the check into noise somebody eventually switches off.
#
# Every other group here has no directive, and that is the right default: months, verbs and
# everyday words are frequent, so if a tier is missing one, **the cut is broken**.
