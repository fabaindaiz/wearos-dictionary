The tool-glue form of the queued candidate: a command-line client that reports an unreachable target on its standard output, with an exit status the caller ignores or swallows, turns every failure into a value. Parse the exit status and the transport's own error markers as a refusal, and keep "could not ask" distinct from "absent".

## Evidence

A second repository (the queued one is a data-analysis repository). A device-bridge client printed its offline error on standard output; the text was read as a device serial, one device counted as two, and the tool gave up with the live one in front of it. A settings read over a dropping connection reported every key as absent. An is-it-installed helper swallowed the exit code and reported the package missing, sending the reader to reinstall over a connectivity failure. A lock-held check matched a history section of the status dump and could only ever answer yes. In measurement scripts of the same repository, a bare exception handler turned a decoding error into a count of zero entries carrying the field, and a misremembered field name returned zero entries; both read like answers, and the second was caught only because zero was implausible.
