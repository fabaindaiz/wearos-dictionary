Two boundaries. (a) An interface method given a neutral default lets every test double silently answer "nothing" while the real implementation answers; leaving it abstract forces each double to answer, and the main fake can derive its answer from its own data. (b) A headless renderer is a double of the screen: stub font metrics, no colour, no animation, so a constant calibrated against it is calibrated against fiction. What worked: give the datum a carrier that is not a pixel (an accessibility state description the test can read), move the arithmetic into a pure function, and measure an animation by counting brightness steps over a screen recording instead of looking at frames.

## Evidence

One repository: a settings-callback double recorded a value while the real callback changed the display density, the entire cause of the defect, so the test could not fail; the note's own check was recorded as not run that day. In one session three green-but-blind cases: colour, animation and where a line breaks (the stub metrics lay text out at about two and a half times the font size). The no-default rule was applied deliberately to a new data method so that every one of several doubles had to answer it.
