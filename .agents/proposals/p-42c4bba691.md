Tests written for a function the agent has just written cover the function and not the line that carries its result into the system: the argument passed to it, the call from the entry point, the assignment into the artefact, the lookup that feeds a view. Mutating that call site (the argument replaced by a null, the call deleted, the assignment made a no-op) survives while every mutation of the function itself bites. After a function's tests, mutate its call site; where that survives, extract the transport into a pure function with its own test. Stops applying where an end-to-end test already runs the real entry point on an input that tells the cases apart. Costs one more mutation per new function.

## Evidence

In one repository, five occurrences in two days and one a week earlier: a build option parsed and wired to nothing, so the artefact came out byte-identical; a constraint check that the entry point never called; a value read inline in the app's composition root, replaceable by a literal null with every test green; the line writing a per-rule ledger into the artefact, replaceable by a no-op; and earlier a setting that persisted and read back correctly but was consumed only at construction, so changing it changed nothing. A sixth form: a screen test fed its list directly while production filters that list upstream, so the feature never rendered; only the emulator showed it. Four of the five were caught only by mutation. The extraction that worked, twice: the transport became a pure function with its own test.

Overlaps principle 18's mention of the stub that is never consulted, and the queued `unconsulted-parameter-is-still-a-contract`. Literature: mutation tools ship call-removal operators (for example the void and non-void method-call mutators of a common JVM mutation tool); ASSUMPTION, not checked against the source.
