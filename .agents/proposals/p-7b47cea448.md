A new boundary for the queued candidate: the input a surviving guard needs is often present in the real data and absent from the fixtures, so run the surviving mutant against the production corpus before deleting the guard. When the input is absent from all real data today, the guard stays only as a declared specification, pinned by a synthetic test that says so in a comment.

## Evidence

A second repository (the candidate came from an app with an on-device suite). Five occurrences in about a week: a branch whose removal changed nothing in the suite was, over the two real sources, the only rescue for tens of records, so it earned a test instead of a deletion; a prefix-instead-of-exact mutation survived until the real data showed words that share the prefix (a handful of real keys destroyed); a guard whose trigger does not occur at all in today's source was kept, as specification for the next one; two tests that could not reach their branch (a declaration cycle in which nothing is absorbed, and a fixture whose key made the precedence unobservable); two fixtures in which the case never occurred (a cut that happened to land on a boundary, and no punctuation at the cut).
