# Proposal: cite-or-read-before-asserting

A statement to the owner about what the code does, or about what a past event was, is cited by file and line or read before it is made. Memory and inference are marked as such, and an event that looks like a loss or a fault is checked against the record of who caused it before it is called one.

## Evidence

One carrier, one owner, with one further occurrence seen in a second carrier of that owner. Three false statements in the first carrier, each corrected in the following message or at the close: a background job was described as queued by the new build when the code has no such origin and the job belonged to the previous build; a case was attributed to the wrong rule; and a history count that dropped was reported as a possible data loss when the owner had cleared it, which had already happened once before in the same way. A smaller form of the same slip appeared in the log earlier: a number asserted before the function computing it was read, and a size estimated from memory that was off by a large margin inside a question to the owner. Literature: the candidate's own; no new source consulted.
