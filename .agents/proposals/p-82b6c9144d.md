# Proposal: reproduce-the-checkout-not-only-the-environment

A gate run in the working tree certifies the working tree, not each commit made from it. A pre-commit hook's subject is the staged snapshot, and the checker it runs is part of that snapshot; a commit series split from one tree needs each intermediate commit gated on its own tree. This narrows the note's Not when, which treats a pre-commit hook as a case where the working tree is the subject.

## Evidence

Two carriers of one owner, so one source. In the first, a new pre-commit hook audited the staged snapshot but at first ran the working tree's audit code over it; it was changed to run the snapshot's own audit. In the same carrier, a two-commit series split from the full tree had a red first commit, found only when that commit was proven in its own worktree, with the rule to do so already loaded. The second carrier built a dedicated tool to split a tree into a gated series for the same reason, and the first gates each commit of a series in a separate worktree as routine. Literature: the note's own.
