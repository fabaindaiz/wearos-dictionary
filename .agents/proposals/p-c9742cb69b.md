# Proposal: decisions-migrate

`bundle.py decisions --migrate --write` rebuilds each row from its parsed cells and writes them back joined with ` | `, which drops the escape of a literal pipe: `table_cells` turns `\|` into `|`, and nothing escapes it again on the way out. A row whose prose held an escaped pipe outside a code span comes out with one column more, and the same tool's check then fails it as a six-column row. The migration should write each original cell's source text, or escape `|` in every cell outside a code span, and a test should migrate a row holding `a\|b` and read back five cells.

## Evidence

Seen once, in a carrier migrating a four-column log of a few hundred rows: the log held exactly one escaped pipe, inside a row's Why (two backticked words separated by `\|`). After `--migrate --write` that row had six cells, and `bundle.py decisions` reported it as the only error; restoring the backslash by hand made the log pass. The mechanism is visible in the code: `migrate_decisions` builds `cells = [cells[0], status, *cells[1:]]` from `table_cells(line)` and joins them, while `table_cells` unescapes `\|`. Not checked: whether `align` or any other writer that round-trips table rows through `table_cells` has the same loss.
