# dict-data

Opens the packs and runs the queries. It isolates every bit of SQL: `:app` never sees a query.

## Its tests are instrumented, and the gate does not run them

They are the **only** ones that close the assumptions about Android: that the bundled SQLite
carries FTS5, that the prefix uses the covering index on that device, and above all that `norm()`
gives the same thing on the watch as in the builder.

```sh
./gradlew :dict-data:devicePrecheck            # is there anything to run them on? says what is missing
./gradlew :dict-data:connectedDebugAndroidTest # the 36 tests
```

Run them on **every supported API level**, not just one. The whole point of
`NormalizationOnDeviceTest` is precisely that ICU versions differ between Android versions;
running one alone does not prove what the test is trying to prove.

The assets (the toy pack and a copy of the vectors) are generated by `prepareAndroidTestAssets`,
which runs on its own before the build. There is no manual step.

## One connection per pack, on a single-threaded dispatcher

This is not a precaution: the bundled SQLite reports `THREADSAFE=2`, which is multi-thread and
**not** serialized. A connection cannot be used from two threads at once (D-050).

The side effect is useful: queries against the same pack serialise themselves, so an old search
that never finished does not compete with the new one.

## The file to copy

`SqlitePackSource.kt` for a new query: each one documents **why** it has the shape it has, which
is where the knowledge that gets lost lives. `PackFile.kt` for anything that validates a pack: its
four checks cover failures that would otherwise be silent.

## Two things AGP 9 and Gradle 9 will not let you do

Both cost one iteration each and are commented in `build.gradle.kts`:

- **You cannot hand a `Provider` to the SourceSet API.** That is why the generated assets go into
  the static directory `src/androidTest/assets/`, which is gitignored entirely.
- **Referencing something declared at build-script level from inside a `doLast` breaks the
  configuration cache.** It happened with a `copy {}` and then with a helper function. The fix is
  a local lambda or a separate task.

## The fuzzy level's thresholds are provisional

`FUZZY_TRIGGER`, `FUZZY_PREFIX_LENGTH` and `MAX_EDIT_DISTANCE` were chosen a priori and have **no
measurement behind them** (D-052). With a 22-entry pack they mean nothing: they get tuned against
the real pack.

If you are going to touch them, look at `ToyPackFixtureTest` in the builder first — the
instrumented tests depend on the toy pack's content, and that test protects that assumption.
